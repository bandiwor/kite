# Устройство Kite и как его расширять

Этот документ — карта кода: что делает каждая стадия, какие инварианты нельзя ломать и
какие файлы нужно тронуть, чтобы добавить новую возможность.

## 1. Конвейер и размеры

```
&str ─lex─► Vec<Token> ─parse─► Ast ─analyze─► Analysis ─compile─► Proto{Vec<Op>} ─peephole─► run
```

| тип | размер | где |
|---|---|---|
| `Token` | 8 байт | `token.rs` |
| `Node` (узел AST) | 16 байт | `ast.rs` |
| `Op` (инструкция) | 4 байта | `op.rs` |
| `Value` | 8 байт | `value.rs` |

Размеры проверяются `const _: () = assert!(size_of::<…>() == N)`; если после правки сборка падает на таком
assert-е, значит вариант стал слишком широким.

Точка входа — `Vm::eval(name, src)` (`vm.rs`): lex → parse → analyze → compile → run. Всё состояние между вызовами
(интернер, глобалы, куча, `GlobalInfo` с константами) лежит в `Vm`, поэтому REPL просто вызывает `eval` на каждую строку.

### Формат инструкций

`Op` — `#[repr(u8)] enum` ровно в 4 байта: байт тега и до трёх байт операндов (`u8`, `u16`, `(u8, u8)`, `(u8, u16)`
или 24-битные `U24`/`I24` для индексов констант, глобалов и смещений переходов). Пример: `Const(U24)`,
`GetLocal(u16)`, `AddLocalK(u8 слот, u16 константа)`.

Если операндов не хватает, инструкция **двойная**: за словом с кодом и операндами идёт слово `Op::Ext(I24)` со
смещением перехода. Двойные — слитые «сравнение + переход» (`JNotLtLL`, `JNotLtLK`, …) и циклы
(`ForPrep`, `ForLoop`, `IterNext1/2`). `Op::width()` — 1 или 2; смещения считаются в словах от слова,
следующего за инструкцией (за `Ext` у двойной). Слитые варианты со слотом ≥ 256 или константой ≥ 65536 пипхол
просто не создаёт, остаётся обычная последовательность. `op::verify` проверяет структуру кода (в debug-сборке
вызывается для каждой функции). VM читает 24-битные операнды прямо из слова (`Op::imm24/simm24`) — это опирается
на `#[repr(u8)]` и проверено юнит-тестом.

## 2. Лексер (`lexer.rs`)

Один проход по байтам, результат — `Vec<Token>` с `Eof` в конце. Токен — это только `(kind, start, len)`:
лексер не превращает «123» в число, не раскрывает escape-последовательности и не интернирует идентификаторы.
Ошибки (неизвестный символ, незакрытая строка/комментарий) — токен `Error`; сообщение формирует парсер.
Ключевые слова распознаются `match`-ом по срезу байтов. `1..5` лексируется как `1` `..` `5`: дробная часть берётся
только если после точки идёт цифра. `is_incomplete` используется REPL, чтобы понять, что нужна следующая строка.

## 3. Парсер и AST (`parser.rs`, `ast.rs`)

* **Pratt**: `parse_bp(min_bp)`; `infix_bp(kind)` — один `match` (таблица переходов). Левоассоциативный оператор
  `(l, l+1)`, правоассоциативный `(l, l)`. Постфиксные `(`, `[`, `.`, `:` — самые сильные (140), унарные — 120,
  `**` — 130 (сильнее унарного минуса).
* Дети хранятся индексами: `NodeId(u32)`; списки (аргументы, операторы блока, пары таблицы) — диапазон `ListRef`
  в общем `Vec<u32>`. Пока список строится, элементы лежат на общем `scratch`-стеке парсера и копируются в AST
  один раз (никаких `Vec` на узел).
* Позиция (`u32`-смещение) узла лежит в параллельном `spans`. Бинарные узлы, вызовы и обращения позиционируются
  на токен оператора (`.`/`(`/`+`) — так ошибки указывают на правильную строку в многострочных цепочках.
* `Block { stmts, tail }`: `tail` — последнее выражение без `;`; оно же значение блока.
* **Блок или таблица?** `brace_is_table(Brace::{Stmt, Lambda, Expr})`. В начале оператора `{` — блок, кроме `{ ключ: …` /
  `{ ключ, …`; после `=>` и `|x|` — тот же выбор; в позиции выражения `{` — блок, если не похож на таблицу (`{}`,
  `{k:`, `{"k":`, `{1:`, `{[…]:`, `{a,`); `{ident}` — таблица, если рядом нет бинарного оператора. Блок-оператор,
  за которым стоит бинарный оператор (`continues_after_block`), продолжается как выражение: `{1} + {2}`.
* **Присваивание — оператор.** `parse_expr()` его не принимает; `parse_expr_assign()` (выражение-оператор, тело `=>`,
  ветка `match`, хвост блока) принимает одно присваивание верхнего уровня. Поэтому `a = b = c` и `while a = b` — ошибки.
* `;` необязательна после выражения, заканчивающегося `}`.
* Ошибки: `PResult<T> = Result<T, ()>`, диагностика копится в `errors`; `synchronize()` пропускает токены до `;`
  или ключевого слова оператора. Глубина вложенности ограничена (200), чтобы не переполнить стек.

## 4. Анализатор (`analyzer.rs`)

Один обход, результат — `Analysis`:

* `res[node]` — для `Ident` и объявлений: `Local(slot) | Upvalue(i) | Global`; для узлов, открывающих область
  видимости (блок, цикл), — нижайший **захваченный** слот внутри (`Local(m)`), с которого нужно закрыть upvalue.
* `funcs[id]` — `FuncInfo { nslots, upvals }`; `for_base[id]` — первый скрытый слот цикла `for`.
* Слоты выдаются по областям видимости с повторным использованием. Кадр = `[слоты…][временные операнды…]`, поэтому
  компилятору не нужно знать, где «сейчас» лежит локальная переменная, даже если она объявлена в середине выражения.
* Верхний уровень чанка — **глобальные**: плотные индексы `Sym` в `Vm::globals`. `hoist_globals` заранее
  регистрирует имена верхнего уровня (функции видят константы, объявленные ниже; присваивание к `const` ловится сразу).
* Для `var/const` с лямбдой в инициализаторе имя объявляется **до** тела — работает самоссылка.

## 5. Компилятор (`compiler.rs`)

* `expr()` оставляет ровно одно значение на стеке, `stmt()` — ноль. `FnBuilder.depth` отслеживает глубину по
  `Op::stack_effect()`; она нужна для `break`/`continue` (выбросить временные: `PopN(depth - loop.depth)`) и для
  размера кадра (`max_stack`).
* `break`/`continue`/`return` — выражения: после них выдаётся мёртвый `Nil`, чтобы модель стека осталась
  согласованной (peephole его удалит).
* `cond_false` / `cond_true` компилируют `&&`, `||`, `!` в переходы без материализации bool.
* Циклы: `LoopCtx { depth, breaks, continues, close }`. Значение `while`/`for` без `break` — `nil` (метка `Nil`
  после выхода по условию), `break v` приходит на метку после неё со значением на стеке.
* `for i in a..b` → `ForPrep/ForLoop` над скрытыми слотами; `for [k,] v in t` → `IterNext1/2`.
* Конструктор (`fn new` в `impl`) компилируется с `is_ctor`: любой выход возвращает `GetLocal(0)` (self).
* Сворачивание констант — `const_num` (глубина ≤ 8). Поля/имена методов — интернированные строки в `consts`.

## 6. Peephole (`peephole.rs`)

Один проход. Входной байткод копируется в буфер `out`; после каждой записи `match_tail` пробует свернуть
хвост буфера (окна 4, 3, 2 инструкции) — поэтому цепочки схлопываются за один проход. Окно нельзя сворачивать,
если внутри него (не считая первой инструкции) есть цель перехода. Переходы в `Entry` хранят **старую абсолютную
цель**; в конце они пересчитываются через таблицу `map: старый индекс → новый`. Поэтому слияния и удаления
безопасны. Условия применимости суперинструкций (слот < 256, константа < 65536) проверяются при слиянии.

## 7. Виртуальная машина (`vm.rs`)

* **Стек**: один буфер на `STACK_SIZE` значений, выделенный один раз (указатели в него стабильны, на слоты
  указывают открытые upvalue). Кадр: `base` = первый аргумент; слот `base-1` — вызываемое значение (при возврате
  туда кладётся результат).
* **Вызов** (`call_value_at`): замыкание → `push_frame` (проверка арности и стека, обнуление локалов); нативная
  функция → вызов `fn(&mut Vm, &[Value])`; `struct` → создание экземпляра и вызов `new` (аргументы сдвигаются на
  одну позицию, чтобы вставить `self`); экземпляр → хук `call`.
* **Re-entrancy**: хуки операторов, `print` с `str`, `sort/map/catch_panic` вызывают `Vm::call_value`, который запускает
  вложенный `run(stop)` до возврата на глубину `stop`. Глубина вложенности ограничена (`MAX_NEST`).
* **Хвостовые вызовы**: peephole превращает `Call; Return` в `TailCall; Return`. `TailCall` для замыкания
  переиспользует кадр; для всего остального работает как `Call`, а следующий `Return` вернёт результат.
* **Upvalue**: пока переменная жива, upvalue указывает в стек (`open_upvals` отсортирован по адресу);
  `CloseUpvals(slot)`, `Return` и раскрутка при ошибке копируют значение внутрь upvalue.
* **Ошибки**: `RtResult<T> = Result<T, Box<RtError>>`. Трассу собирает внешняя обёртка `run` из `frames` в момент
  выхода ошибки; перехватывает `catch_panic` (`call_protected` восстанавливает кадры, `sp` и upvalue).
* Медленные пути (`arith_slow`, `compare_slow`, `get_field_slow`, …) — отдельные методы; быстрые пути
  (числа, поля экземпляров, чтение таблиц) — прямо в `match`.

## 8. Значения, куча, GC

* **NaN-boxing** (`value.rs`): всё, что не имеет в экспоненте+старшем бите мантиссы маску `0x7FFC…`, — `f64`.
  Иначе знаковый бит различает указатель на объект (48 бит) и синглтоны (`nil`, `true`, `false`, `UNDEF`
  — неопределённый глобал, `TOMB` — удалённая запись хеша). Машинные NaN (`0x7FF8…`, `0xFFF8…`) под маску не попадают.
* **Объекты** (`object.rs`): `Str`, `Table`, `Proto`, `Closure`, `Upvalue`, `Native`, `StructType`, `Instance`.
  Все `#[repr(C)]` с `Header { kind, marked, next }` первым полем; `Gc<T>` — копируемый указатель.
* **Строки**: интернированные (константы, имена полей, идентификаторы) сравниваются по указателю; динамические
  (результат конкатенации) — по содержимому; хеш кешируется в объекте.
* **GC** (`heap.rs` + `Vm::collect_garbage`): stop-the-world mark & sweep с серым стеком. Корни: стек до `sp`,
  кадры, глобалы, открытые upvalue, очередь финализаторов. Запускается **только в safe point** — после
  инструкций, которые аллоцируют (`gc_check!`), когда всё живое достижимо из корней. Порог — `max(1 МБ, 2 × живое)`.
* **Финализаторы**: недостижимый `Instance` с методом `destroy` воскрешается один раз и ставится в очередь;
  `destroy` выполняется после sweep, объект освобождается следующей сборкой. При выходе (`Vm::shutdown`)
  `destroy` вызывается для всех живых экземпляров в порядке создания.
* **Таблица** (`table.rs`): `arr` (ключи `0..n` без дыр) + хеш-часть в порядке вставки (вектор записей + индекс с
  линейным пробированием; удаление ставит `TOMB`). Хеш-часть до 8 записей — без индекса (линейный поиск).

### Модули

`analyze(.., module = true)` делает верхнеуровневые имена файла локалами «функции-модуля»: `hoist_module` заранее выдаёт
слоты (поэтому ранние функции видят поздние, а замыкания захватывают слоты как upvalue и держат состояние модуля
после его завершения) и собирает `exports`. Компилятор (`module_root`) в конце строит таблицу экспортов и возвращает её.
`import` компилируется в `Import(путь)` (+ `GetExport` для именованных имён); загрузчик `Vm::import_module` ищет файл,
кэширует результат в `modules` (значения — корни GC), компилирует `compile_chunk(.., module = true)` и запускает
через `call_value`, поэтому модули могут импортировать другие модули.

### Union и match

`union` использует тот же `StructType`, что и `struct`: у типа есть `variants: Vec<Variant{name, fields, value}>`, а у
`Instance` — `tag: u16` (индекс варианта). Вариант без полей — один общий экземпляр (`Variant.value`), вариант с полями —
`VariantCtor{ty, tag}` (`Kind::Variant`), вызываемый объект. `Type.Variant` ищется в `get_field_slow`, поля варианта —
обычные поля экземпляра (по имени из объявления). Хуки и `impl` работают как у структур.

`match` компилируется в цепочку проверок без выделений: выражение кладётся в скрытый локал, каждая ветка — набор
`pat_test` (литерал → `Eq`+переход; вариант → `IsVariant(arity, имя)` / `IsVariantQ` с проверкой типа-квалификатора;
`Unpack(n)` кладёт поля в слоты привязок), затем охранное условие и тело. Альтернативы `p | q` переиспользуют слоты
привязок (анализатор проверяет одинаковость наборов имён). Если у ветки есть захваченные привязки, в конце ветки идёт
`CloseUpvals`. Неподошедшее значение попадает в `MatchFail` (ошибка с отображением значения). Все четыре опкода — обычные
4-байтовые слова (`(u8, u16)`: порядок полей важен, см. «Формат инструкций»).

### Массивы

`Kind::Array` — `Array { items: Vec<Value> }` (`object.rs`). Литерал `[..]` компилируется в `NewArray` + `Append` на каждый элемент
(`nil` допустим). `GetIndex`/`SetIndex` проверяют `Array` первым (`array_slot` — быстрый путь для целой позиции в границах),
остальное попадает в `get_index_slow`/`set_index_slow`, где `array_position` формулирует ошибку (паника). Итерация —
`IterNext` с курсором-позицией. Методы `arr:f()` ищутся в таблице `array` (`Vm::array_lib`, аналог `string_lib`), поэтому любая
функция библиотеки `array` одновременно и функция, и метод. Всё, что возвращает «может не быть», возвращает `Option`
(`make_some/make_none`). Массивная часть `Table` осталась внутренней оптимизацией таблиц с ключами `0..n`.

### Библиотеки

`builtins.rs` регистрирует ядро и таблицы-библиотеки (`lib(vm, "math", &[(имя, арность, fn)])`), `fslib.rs` — `fs`. Новая
библиотека — отдельный файл с `install(vm)`, который вызывается из `builtins::install`; всё, что может не получиться по внешним
причинам, возвращает `Result` через `vm.make_ok/make_err/make_error`, а неверные аргументы — паника (`rt_err`).

### Prelude, Option/Result/Error и `?`

`prelude.kite` — часть стандартной библиотеки, написанная на самом Kite (`Option`, `Result`, `Error` и их методы). Она
выполняется один раз в `Vm::new` (`prelude.rs`), после чего `Vm` запоминает три типа в полях `option_ty/result_ty/error_ty`
(корни GC): через них нативные функции строят значения (`make_ok/make_err/make_some/make_none/make_error`), а `Op::Try`
разбирает их (`split_try`: тег 1 — полезный вариант у `Option`, тег 0 — у `Result`; порядок вариантов в prelude —
часть контракта). Кадры с источником `<prelude>` убираются из трассы ошибки, так что паника в `unwrap` указывает на строку
вызывающего. Чтобы добавить метод или тип — допишите Kite-код в `prelude.kite`; если нужна скорость или доступ к VM, пишите нативную функцию.

`expr?` — постфиксный оператор (`Node::Try`, `Op::Try`): для `Ok/Some` заменяет значение на его содержимое, для `Err/None`
выполняет `do_return!` с самим значением (закрывая upvalue кадра, как обычный `return`).

Модель ошибок: ожидаемые неудачи — значения (`Result`/`Option`), баги — паники (`RtError`, разматывает стек до границы
`call_protected`). `catch_panic` — единственная точка, где паника превращается в значение.

## 9. Рецепты расширения

### Новый бинарный оператор (например, `//` — целочисленное деление)

1. `token.rs`: вариант `SlashSlash` (+ `describe`); `lexer.rs`: распознать в ветке `b'/'`.
2. `ast.rs`: вариант `BinOp::IntDiv`.
3. `parser.rs`: строка в `infix_bp` (приоритет) и в `binop`.
4. `op.rs`: вариант `Op::IntDiv` и строка в `stack_effect` (−1).
5. `compiler.rs`: ветка в `binop()`; при желании — свёртка в `const_num`.
6. `vm.rs`: вариант `Arith::IntDiv` (символ для сообщений, `arith_num`, хук), обработчик в `run_inner`
   по образцу `Op::Sub` (макрос `arith!`). Если нужна перегрузка — добавить `Hook::IntDiv` в `object.rs`
   (константа `HOOK_COUNT`, `Hook::from_name`).

### Новая инструкция / суперинструкция

1. `op.rs`: вариант (укладывайтесь в 4 байта; не помещается — делайте двойной через `is_wide` и `Ext`), `stack_effect`, при ветвлении — `jump_offset`/`with_jump_offset` (или `is_wide`). Двойные инструкции в компиляторе эмитятся через `emit_wide` и патчатся `patch_to`.
2. `vm.rs`: обработчик. Помните про `sync!()` перед всем, что может завершиться ошибкой (`protect!` делает это сам)
   и про `gc_check!()` после аллокаций.
3. Суперинструкция — правило в `peephole::match_tail` (+ символ в `can_end_window`, если окно заканчивается новым
   опкодом) и юнит-тест в `peephole.rs`. `disasm.rs` печатает всё через `Debug`; добавьте заметку о константе, если нужно.
4. Проверьте частоту паттерна: `cargo build --release --features op-profile`.

### Новая встроенная функция или библиотека

В `builtins.rs`: `fn name(vm: &mut Vm, args: &[Value]) -> RtResult<Value>` и строка в `install`
(`vm.define_native("name", arity, name)`, арность `-1` — переменное число аргументов). Модуль — `lib(vm, "имя", &[…])`.
Правила безопасности для GC: нативные функции могут свободно создавать объекты (аллокация сама никогда не запускает
сборку), но если функция **вызывает обратно в VM** (`call_value`), свежие объекты нужно удерживать через
`vm.root(v)` / `vm.unroot(n)`, а значения из таблицы читать по курсору (`Table::next`), а не копировать заранее.

### Новый хук (`foo` для структур)

`object.rs`: вариант `Hook::Foo`, `HOOK_COUNT`, строка в `Hook::from_name`. Затем в нужном месте VM:
`self.instance_hook(value, Hook::Foo)` и `self.call_value(f, &[…])`.

### Новый тип объекта кучи

`object.rs`: структура `#[repr(C)]` с `hdr: Header` первым полем, `impl GcObj` (`KIND`, `heap_size`), вариант `Kind`;
`heap.rs`: ветки в `blacken`, `obj_size`, `free_obj`; `value.rs`: имя в `type_name`; `vm.rs`: отображение в `write_value`.

### Новая синтаксическая конструкция

`ast.rs` (вариант `Node`, держите 16 байт — тяжёлые данные выносите в отдельный `Vec`, как `FuncDef`/`ForDef`) →
`parser.rs` (`parse_prefix`/`parse_stmt`) → `analyzer.rs::expr` (области видимости, слоты) → `compiler.rs::expr/stmt`
(+ `ast.rs::dump` для `--dump-ast`). Если конструкция вводит область видимости с замыканиями, повторите схему
`push_scope`/`pop_scope` и запись `res[node] = Local(captured_min)`.

## 10. Инварианты, о которые легко споткнуться

* Любой путь, который может вернуть `Err`, в `run_inner` обязан сначала сохранить `ip`/`sp` (`protect!`/`throw!`),
  иначе трасса и сборка мусора увидят устаревшее состояние.
* `Value::as_gc_unchecked` допустим только там, где тип гарантирован компилятором (константы, скрытые слоты);
  значения из пользовательского кода проверяйте `as_gc::<T>()`.
* Смещения переходов считаются от **следующей** инструкции. `with_jump_offset` возвращает `None`, если число
  не помещается в `i16` — вызывающий код обязан это обработать.
* Глубина модели стека в компиляторе после «расходящихся» выражений (`break`, `return`) восстанавливается вручную
  (`set_depth` + мёртвый `Nil`).
* Объекты, созданные компилятором (прототипы, строки, шаблоны структур), живы, пока на них ссылаются константы
  прототипа; GC не запускается между компиляцией и началом выполнения.
