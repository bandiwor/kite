# Kite

Небольшой, быстрый, динамически типизированный язык, ориентированный на выражения.
Компилятор и виртуальная машина написаны на Rust без внешних зависимостей.

```kite
const PI = 3.14;
var x = 10;
x += 10;

const val = loop {
    break 42;
}

while val < 10 {
    continue; break;
}

fn add(a, b) {
    return a + b;
}
const mul = |a, b| => a * b;
```

* **Динамические типы**: `nil`, `bool`, `number` (f64), `string`, `array`, `table`, функции, `struct`, `union`.
* **Всё — выражение**: `if`, блоки, `loop`, `while`, `for` возвращают значения, `break value` выносит значение из цикла.
* **Замыкания** с настоящим захватом переменных (upvalue), своя свежая переменная на каждую итерацию цикла.
* **`array`** — настоящий массив: позиции `0..len`, хранит любые значения (в том числе `nil`), доступ с проверкой границ.
* **`table`** — хеш-таблица. Ключ — любое значение, кроме `nil` и `NaN`.
* **Без ООП**: `struct` с фиксированными полями, `impl` добавляет обычные функции; особые имена (`new`, `destroy`,
  `add`, `eq`, `str`, …) VM использует как перегрузки операторов и жизненный цикл.
* **NaN-boxing** (значение = 8 байт), **4-байтовые инструкции** (длинные — двойные), **сборщик мусора** mark & sweep с финализаторами (`destroy`).
* **Интерактивный режим** (REPL) с многострочным вводом.

## Быстрый старт

```sh
cargo build --release
./target/release/kite                    # REPL
./target/release/kite examples/hello.kite
./target/release/kite -e 'print(1 + 2)'
```

Опции: `--dump-ast`, `--dump-bytecode`, `--no-opt` (без peephole), `--gc-stress` (сборка на каждом safe point),
`--time` (время по фазам компиляции), `-` (читать программу из stdin).
В REPL есть команды `:help`, `:bytecode`, `:ast`, `:opt`, `:gc`, `:mem`, `:globals`.
Для истории и редактирования строки запускайте `rlwrap kite`.

```
>>> fn double(n) { n * 2 }
>>> double(21) + 0
=> 42
>>> [1, 2, { a: "b" }]
=> [1, 2, {a: "b"}]
```

## Язык

### Данные и операторы

```kite
nil  true  false                 // литералы
42  3.14  1_000  0xFF  0b101  1e-3   // числа — всегда f64
"строка\n"  'или так'  "\u{1F600}"   // строки (UTF-8), escape: \n \t \r \0 \\ \" \' \xHH \u{...}
```

Ложны только `nil` и `false` (`0` и `""` истинны). Приоритеты, от слабых к сильным:

| | |
|---|---|
| `=` `+=` `-=` `*=` `/=` `%=` `**=` `&=` `\|=` `^=` `<<=` `>>=` | присваивание (правоассоциативно; это выражение) |
| `\|\|` | или (возвращает операнд, как в Lua) |
| `&&` | и |
| `==` `!=` | равенство |
| `<` `<=` `>` `>=` | сравнение (числа и строки) |
| `\|` · `^` · `&` | побитовые (над i64) |
| `<<` `>>` | сдвиги |
| `+` `-` | сложение; если один операнд строка — конкатенация (`"n=" + 5`) |
| `*` `/` `%` | деление на ноль даёт `inf`/`nan`, ошибки нет; `%` как fmod |
| `-x` `!x` `~x` | унарные |
| `**` | степень, правоассоциативна, сильнее унарного: `-2 ** 2 == -4` |
| `f(x)` `t[k]` `t.name` `obj:method(x)` | постфиксные |

### Переменные

```kite
const PI = 3.14;      // привязка нельзя переприсвоить (содержимое таблиц менять можно)
var x = 1;            // изменяемая
var y;                // nil
```

Переменные верхнего уровня файла — глобальные (функции могут ссылаться на объявленное ниже).
Внутри функций и блоков — локальные с лексической областью видимости; повторное объявление в той же области — ошибка.
В REPL глобальные можно объявлять заново.

### Выражения и управление

```kite
const size = if n > 10 { "big" } else if n > 5 { "mid" } else { "small" };
const v = do { var t = compute(); t * 2 };     // блок-выражение: значение последнего выражения без `;`

while cond { ... }                // значение — nil или то, что передал break
const r = loop { ...; break 42; } // бесконечный цикл, значение — break
for i in 0..10 { ... }            // диапазон [0, 10); границы вычисляются один раз
for v in table { ... }            // значения (сначала массивная часть, потом в порядке вставки)
for k, v in table { ... }         // ключ и значение
for ch in "héy" { ... }           // по символам строки (при двух переменных ключ — смещение в байтах)
break; break value; continue;     // можно и внутри выражения: f(1, if c { break 5 } else { 2 })
return; return value;             // в любом месте выражения
```

Точка с запятой не нужна после выражения, заканчивающегося `}` (`if`, `loop`, `const x = loop {…}`).

Блок — полноценный операнд: `{1} + {2}`, `x * { var t = f(); t + 1 }`, `|a| => {a} + {1}`. `{` в позиции выражения — это блок,
если только он не похож на таблицу (`{}`, `{k: …}`, `{"k": …}`, `{1: …}`, `{[k]: …}`, `{a, …}`); одиночное `{name}` — таблица-сокращение,
если рядом нет бинарного оператора. В начале оператора `{ … } + x` продолжается как выражение (`{ … }` и `do { … }` без оператора после — обычный оператор).

**Присваивание — оператор, а не значение.** `a = b = c`, `while a = b { }`, `if a = 1 { }`, `f(a = 1)`, `x + (a = 2)` — ошибки компиляции
(«did you mean `==`?»). Присваивание допустимо как выражение-оператор, как тело `=>`-лямбды и ветки `match`, и как последняя строка блока.

### Функции и замыкания

```kite
fn add(a, b) { return a + b; }       // объявление; последнее выражение без `;` — результат
fn sq(x) { x * x }
const mul = |a, b| => a * b;         // лямбда: выражение
const inc = |x| { var y = x + 1; y } // лямбда: блок (`=> { ... }` тоже блок; `=> { key: v }` — таблица)
const k = || => 42;
const anon = fn (a) { a + 1 };

fn counter() {
    var n = 0;
    return || => { n += 1; n };      // n живёт, пока жива лямбда
}
```

Число аргументов проверяется строго. Хвостовые вызовы не растут по стеку (`return f(x)`).
Рекурсия по имени работает и для `const f = |x| => … f(x-1)`.

### Массивы

```kite
const a = [10, nil, 30];           // nil — обычный элемент: len(a) == 3
push(a, 40, 50);  a:push(60);      // функция или метод; возвращают новую длину
a[0] += 5;                         // читать и писать можно только существующие позиции
a[9];  a[-1];  a[1.5];  a[3] = 0;  // паника: index out of bounds / must be a non-negative integer
a:get(9);                          // None; a:get(0) — Some(15): проверяемый доступ возвращает Option
pop(a);                            // Some(60) или None — nil может быть элементом, поэтому Option
for v in a { … }   for i, v in a { … }
print(map(a, |x, i| => x), array.new(3, 0), [1, 2, 3]:slice(1));
```

`[1, nil]` и `push(a, nil)` сохраняют `nil`; массив не растёт присваиванием (`a[len(a)] = v` — паника, используйте `push`) и никогда не
превращается в хеш-таблицу. `==` сравнивает массивы по идентичности (как таблицы); `copy()` — поверхностная копия.

| | |
|---|---|
| `push(a, v…)` `pop(a)` `insert(a, i, v)` `remove(a, i)` `clear(a)` | изменение (`i` для `insert` ≤ длины); `pop` → `Option`, `remove` → элемент |
| `get(a, i)` `first(a)` `last(a)` `index_of(a, v)` `contains(a, v)` | проверяемый доступ и поиск → `Option` (`contains` → bool) |
| `slice(a, from, to?)` `concat(a, b…)` `copy(a)` `extend(a, b)` `reverse(a)` `sort(a, less?)` | `slice/concat/copy` — новый массив; `extend/reverse/sort` — на месте, возвращают `a` |
| `map filter reduce each(a, f)` | `f(x)` или `f(x, i)`; `map`/`filter` возвращают массив |
| `join(a, sep?)` `keys(a)` `values(a)` `has(a, i)` `len(a)` | |
| `array.new(n, fill?)` | массив из `n` копий |

Все они есть и как обычные функции (`push(a, 1)`), и как методы (`a:push(1)`) — это одна и та же таблица `array`. `"a,b":split(",")`,
`s:chars()`, `fs.list` и `fs.lines` возвращают массивы.

### Таблицы

```kite
const t = { name: "kite", "two words": 2, [1 + 1]: "computed", 3: "x" };
t.name = "KITE";  t["k"] = 1;  t.k += 1;
t.name = nil;                      // присвоение nil удаляет ключ
print(len(t), t.missing);          // отсутствующий ключ — nil
```

Ключи-строки сравниваются по содержимому, числа — по значению (`1 == 1.0`, `-0 == 0`), остальное — по идентичности.
`nil` и `NaN` ключом быть не могут (запись — ошибка). Таблица `{ x }` — сокращение для `{ x: x }`.
В позиции начала выражения-оператора `{ ключ: …` — таблица, иначе `{` — блок; в остальных местах `{` — таблица.
Явный блок-выражение: `do { … }`.

### Структуры, перегрузки, `new` и `destroy`

```kite
struct Vec2 { x, y }               // фиксированный набор полей, изначально nil

impl Vec2 {
    fn new(self, x, y) { self.x = x; self.y = y; }    // конструктор: Vec2(1, 2)
    fn add(a, b) { Vec2(a.x + b.x, a.y + b.y) }       // a + b
    fn eq(a, b)  { a.x == b.x && a.y == b.y }         // a == b
    fn str(a)    { "(" + a.x + ", " + a.y + ")" }     // print / str / конкатенация
    fn destroy(self) { print("bye", self) }           // при сборке мусора и при выходе
}

const v = Vec2(1, 2) + Vec2(3, 4);
print(v, v.x, Vec2.add(v, v), v:length());            // v:f(a) то же, что Vec2.f(v, a)
```

Без `new` конструктор принимает значения полей по порядку. Результат конструктора — всегда новый экземпляр.

| имя | когда вызывается |
|---|---|
| `new(self, …)` | `Type(…)` |
| `destroy(self)` | экземпляр недостижим для GC, явный `destroy(x)`, завершение программы |
| `add sub mul div rem pow (a, b)` | бинарные операторы (ищутся у левого, затем у правого операнда) |
| `neg(a)` | унарный минус |
| `eq(a, b)` | `==` и `!=` |
| `lt(a, b)` `le(a, b)` | `<`, `>` (через `lt`), `<=`, `>=` (через `le`, иначе `!lt`) |
| `str(a)` | `print`, `str()`, конкатенация со строкой |
| `len(a)` | `len(x)` |
| `get(a, k)` `set(a, k, v)` | `a[k]`, `a[k] = v` и обращения к несуществующему полю |
| `call(self, …)` | вызов экземпляра как функции |

Остальные функции из `impl` — обычные: `Type.name(...)` или `obj:name(...)`. `type(x)` для экземпляра возвращает имя структуры.
Деструкторы вызываются в порядке создания; ошибка в `destroy` печатается как предупреждение и не прерывает программу.

### Union и `match`

`union` — размеченное объединение (как `enum` в Rust): у каждого варианта своё имя и набор полей.

```kite
union Shape {
    Circle(radius),          // вариант с данными
    Rect(w, h),
    Point,                   // вариант без данных (единственный общий экземпляр)
}

const c = Shape.Circle(2);
print(c, c.radius, type(c), type(Shape));      // Circle(2) 2 Shape union
c.radius = 5;                                  // поля вариантов читаются и пишутся по имени
const make = Shape.Rect;                       // конструктор — обычная функция: map(xs, Shape.Circle)

impl Shape {                                   // impl, перегрузки и destroy — как у структур
    fn area(self) {
        match self {
            Circle(r) => 3 * r * r,
            Rect(w, h) => w * h,
            Point => 0,
        }
    }
}
print(c:area());
```

`match` — выражение: берётся первая подошедшая ветка, значение — её тело. Если ничего не подошло — ошибка времени выполнения
(`no match arm matched the value …`). Выражение проверяется один раз.

| образец | значит |
|---|---|
| `_` | что угодно |
| `name` (с маленькой буквы) | что угодно, значение связывается с `name` |
| `0`, `-1`, `"s"`, `true`, `false`, `nil` | равенство с литералом |
| `Circle(r)`, `Rect(w, _)` | вариант (любого union) с таким именем; поля сопоставляются по порядку, число образцов обязано совпасть |
| `Circle` | вариант с любым числом полей |
| `Shape.Circle(r)` | то же, но ещё и проверка, что значение именно из `Shape` (`Shape` — любое выражение-путь, например `mod.Shape`) |
| `Pt(x, 0)` | экземпляр структуры `Pt`, поля по порядку |
| `p \| q` | любая из альтернатив; все должны связывать одни и те же имена |
| `pat if cond` | образец + охранное условие (видит связанные имена; если ложно — идём к следующей ветке) |

Образцы вкладываются: `Add(Num(0), r) | Add(r, Num(0)) => simplify(r)`. Имя образца, начинающееся с заглавной буквы, — это вариант,
с маленькой — привязка. Ветки — через запятую; тело — выражение, блок или присваивание: `n => total += n`, `_ => {}`.
Связанные имена можно захватывать замыканиями, каждое вычисление `match` даёт свежие переменные.

### Модули

Файл — это модуль. Его верхнеуровневые имена **приватны**, наружу уходит только то, что помечено `export`
(`export var/const/fn/struct/union`). Модуль выполняется один раз при первом `import` и возвращает таблицу экспортов:

```kite
// geometry.kite
var created = 0;                          // приватное состояние модуля
export struct Point { x, y }
export fn origin() { created += 1; Point(0, 0) }
export fn how_many() { created }

// main.kite
import "geometry";                         // имя берётся из пути: geometry
import "lib/geometry.kite" as geo;         // или своё имя
import { origin, Point } from "geometry";  // отдельные имена (константы); нет экспорта — ошибка
print(geometry.origin(), geometry.how_many());
```

Путь ищется относительно файла, в котором написан `import` (`путь`, `путь.kite`, `путь/mod.kite`; для REPL и `-e` — относительно
текущей папки). Модуль кэшируется по каноническому пути, циклический импорт — ошибка. Верхнеуровневые функции модуля
видят друг друга независимо от порядка. Экспортируемые `var` — снимок значения на конец инициализации модуля
(для общего изменяемого состояния экспортируйте функции). `import`/`export` допустимы только на верхнем уровне файла,
`return` на верхнем уровне модуля запрещён. В обычном скрипте `export` игнорируется, так что файл может работать и сам по себе.

### Ошибки: `Result`, `Option` и паники

Как в Rust, ошибки двух видов, и try/catch в языке нет.

**Ожидаемые неудачи** (файла нет, строка не число, пустой список) — это **значения**: `Result` (`Ok(v)` / `Err(e)`) и `Option` (`Some(v)` / `None`).
Это обычные union'ы, доступные везде без импорта; `Error` — стандартный тип ошибки (`message`, `kind`).

```kite
fn parse_age(s) {
    const n = parse_num(s)?;                 // Err(..) сразу возвращается из parse_age, Ok(v) даёт v
    if n < 0 { return Err(Error("negative age"):with_kind("range")); }
    Ok(n)
}

match parse_age(input) {
    Ok(n) => print("age", n),
    Err(e) if e.kind == "range" => print("bad range:", e),
    Err(e) => print("error:", e),            // print(e) показывает message
}
```

`expr?` работает и для `Option`: `None` возвращается из функции. Оператор возвращает значение *как есть* (`Err`/`None`) из
ближайшей функции (лямбда — отдельная функция), поэтому он может стоять где угодно в выражении: `Ok(a? + b?)`, `f(x?)`,
`r?.name`. Не `Option`/`Result` — паника. На верхнем уровне модуля `?` запрещён (как `return`).

| Option | |
|---|---|
| `is_some() is_none()` | проверки |
| `unwrap() expect(msg)` | значение или паника |
| `unwrap_or(d) unwrap_or_else(f)` | значение или запасное |
| `map(f) and_then(f) or_else(f) filter(p)` | преобразования |
| `ok_or(err)` | `Option` → `Result` |

| Result | |
|---|---|
| `is_ok() is_err()` | проверки |
| `unwrap() expect(msg) unwrap_err()` | значение (ошибку) или паника |
| `unwrap_or(d) unwrap_or_else(f)` | `f` получает ошибку |
| `map(f) map_err(f) and_then(f) or_else(f)` | преобразования |
| `ok() err()` | `Result` → `Option` |

Сравнение `==` структурное (`Some(1) == Some(1)`). `Error(msg)` создаёт ошибку, `:with_kind("parse")` задаёт категорию
для сопоставления. `Err` может нести любое значение, а не только `Error`. Для перехода от `nil` к `Option` есть `option(x)`,
для чисел — `parse_num(s)` (`Ok(число)` или `Err`). Свои функции стандартной библиотеки, которые могут не получиться, тоже
стоит возвращать как `Result`.

**Паники** — это то, что нельзя «обработать»: баг или невозможная операция (`1 + nil`, индекс вне диапазона, вызов `nil`,
несовпадение арности, `assert`, `panic("msg")`, `unwrap()` у `None`, неисчерпывающий `match`, переполнение стека). Паника
разматывает всю программу и печатает сообщение, фрагмент исходника и стек вызовов (кадры, замещённые хвостовым вызовом,
не видны; кадры prelude скрыты). Деструкторы при этом выполняются.

```kite
assert(cond, "message");   panic("boom");
const r = catch_panic(|| => 1 + nil);   // Err(Error) с kind "panic": последний рубеж для границ программы
```

`catch_panic(f, args…)` возвращает `Ok(результат)` или `Err(Error)`; его место — на границе (тесты, REPL, плагины, обработчик запросов),
а не в обычной логике: ожидаемое выражайте через `Result`.

### Встроенные функции

| | |
|---|---|
| ввод/вывод | `print(...)` (с переводом строки), `write(...)`, `input(prompt?)` |
| типы | `type(x)`, `str(x)`, `num(x)` (nil, если не число; для ошибки с причиной — `parse_num`), `len(x)` |
| массивы | см. «Массивы»: `push pop insert remove get first last slice concat extend reverse copy clear index_of contains join`, `array.new` |
| таблицы | `remove(t, k)`, `keys(t)`, `values(t)`, `has(t, k)`, `len(t)` |
| функциональные | `sort(a, less?)` (устойчивая), `map(c, f)`, `filter(c, f)`, `reduce(c, f, init?)`, `each(c, f)` для массивов и таблиц — если у `f` два параметра, второй получает индекс/ключ |
| ошибки | `assert(c, msg?)`, `panic(msg)`, `catch_panic(f, args…)` → `Result`; `parse_num(s)` → `Result`, `option(x)` → `Option`; `Some Ok Err None Error` |
| система | `clock()`, `time()`, `exit(code?)`, `gc()` (возвращает освобождённые байты), `mem()`, `destroy(x)` |
| `math` | `floor ceil round trunc abs sqrt sin cos tan asin acos atan atan2 exp ln log2 log10 pow min max sign random seed`, `pi e huge` |
| `fs` | `read write append lines exists is_file is_dir size list mkdir remove remove_all rename copy cwd` и пути `join basename dirname stem ext`; см. ниже |
| `string` | `len upper lower trim reverse sub find contains starts_with ends_with split join replace rep chars byte char format`; методы вызываются как `s:upper()` |

### Файлы: `fs`

Операции над файлами целиком (без дескрипторов); всё, что может не получиться из-за внешнего мира, возвращает `Result`,
а `Err(Error)` несёт `kind`: `"not_found"`, `"permission"`, `"exists"`, `"utf8"` (файл не текст) или `"io"`. Сообщение содержит путь.
Передать не строку вместо пути — баг, то есть паника.

```kite
fs.write("notes.txt", "one\ntwo\n")?;           // Ok(nil)
const text = fs.read("notes.txt")?;              // Ok("one\ntwo\n")
for line in fs.lines("notes.txt")? { print(line); }   // без символов конца строки
fs.append("log.txt", "started\n")?;              // создаёт файл, если его нет

match fs.read("config.kite") {
    Ok(src) => run(src),
    Err(e) if e.kind == "not_found" => use_defaults(),     // "config.kite: no such file or directory"
    Err(e) => panic(e),
}
```

| | |
|---|---|
| `read(p)` `lines(p)` `size(p)` | `Ok(текст)` / `Ok([строки])` / `Ok(байты)` |
| `write(p, s)` `append(p, s)` | `Ok(nil)`; `write` создаёт или обрезает файл |
| `list(dir)` | `Ok([имена])`, отсортированные |
| `mkdir(p)` | создаёт и промежуточные папки; уже существующая — не ошибка |
| `remove(p)` `remove_all(p)` | файл или пустая папка / файл или дерево целиком |
| `rename(a, b)` `copy(a, b)` | `Ok(nil)` |
| `exists(p)` `is_file(p)` `is_dir(p)` | `bool` (без `Result`: ошибки доступа читаются как «нет») |
| `cwd()` | `Ok(путь)` |
| `join(a, b, …)` `basename` `dirname` `stem` `ext` | работа со строками-путями без обращения к диску; `ext("Makefile")` → `nil` |

Пример целиком — `examples/files.kite` (CSV → разбор с `?` → отчёт → список папки → уборка).

Индексы строк — в символах Unicode (`s[0]`, `s:sub(1, -1)`, отрицательные считаются с конца).
`string.format("{} {:.2} {:>8} {:<8}", …)`.

## Архитектура

```
 исходник ──► lexer ──► parser ──► analyzer ──► compiler ──► peephole ──► VM
              Vec<Token>  thin AST   слоты, upvalue,  байткод      суперинструкции   NaN-boxing,
              (8 байт)    + Sym      const, break     (слова по 4 б)                    GC, замыкания
```

| модуль | суть |
|---|---|
| `lexer.rs`, `token.rs` | один проход по байтам; токен = `kind:u8 + len:24 бит + start:u32` ровно 8 байт; **ничего не разбирает** (числа и escape-последовательности декодирует парсер по требованию) |
| `parser.rs`, `ast.rs` | Pratt-парсер (таблица bp — один `match`), узлы по 16 байт в одном `Vec` с индексами `u32`, списки детей — диапазоны общего массива, позиции в параллельном `Vec<u32>`; идентификаторы интернируются в `Sym(u32)`, **строковые литералы остаются диапазонами исходника** |
| `analyzer.rs` | разрешение имён (local / upvalue / global), слоты кадра, какие переменные захвачены (для `CloseUpvals`), `const`, `break` вне цикла, повторные объявления |
| `compiler.rs` | стековый байткод; переменные живут в слотах кадра, поэтому выражения вкладываются произвольно; сворачивание констант; условия `&& \|\| !` компилируются в чистый поток управления |
| `peephole.rs` | один проход со слиянием «хвоста» вывода: `Set+Pop→Store`, `cmp+jump`, `x += k`, `GetLocal+GetField`, `Call+Return→TailCall`, протягивание переходов, удаление мёртвого кода |
| `vm.rs` | цикл `match` по 8-байтовым `Op`, регистры (`ip/sp/base/consts`) в локальных переменных, открытые/закрытые upvalue, вызовы замыканий без рекурсии на стеке Rust |
| `value.rs`, `object.rs`, `heap.rs`, `table.rs` | NaN-boxing, объекты кучи, mark & sweep, таблица (массив + упорядоченный open-addressing хеш, до 8 записей без индекса) |

Подробности и рецепты расширения (новый оператор, опкод, встроенная функция, хук, тип объекта) — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Тесты и инструменты

```sh
cargo test                               # юнит-тесты, tests/cases/*.kite (3 режима), примеры
cargo build --release && python3 tools/fuzz.py 300 1     # дифференциальный фаззер
python3 tools/fuzz_match.py 1000 1       # фаззер match: случайные значения × образцы против оракула
python3 tools/fuzz_array.py 1000 1       # фаззер массивов: случайные операции против списков Python
python3 tools/reduce.py SEED             # минимизатор упавшей программы
tools/bench.sh                           # бенчмарки examples/bench
cargo build --release --features op-profile   # частоты опкодов и их пар при выходе
```

Каждый кейс из `tests/cases` запускается обычно, без оптимизатора и со сборкой мусора на каждом safe point
(`// expect:` — ожидаемый вывод, `// error:` — ожидаемая ошибка). Фаззер генерирует случайные программы
(замыкания, циклы с `break`/`continue`, `loop`-значения, затенение переменных, таблицы, структуры с перегрузками,
составные присваивания полей и индексов), считает ответ независимым интерпретатором на Python и сравнивает
с Kite во всех трёх режимах. Таблица дополнительно проверяется случайными операциями против эталонной модели.

Один поток, `cargo build --release`, Xeon 2.8 GHz (замеры на общей машине, разброс ±10%):

|---|---|
| `fib(35)` (рекурсия, 30 млн вызовов) | ≈ 0.7 с |
| цикл `while` на 100 млн итераций | ≈ 0.8 с |
| `for i in 0..50e6 { s += i % 7 }` | ≈ 0.8 с |
| 10 млн вызовов замыкания | ≈ 0.3 с |
| 2 млн коротко живущих таблиц `{a: i, b: [i, i+1]}` | ≈ 0.7 с |

compile + peephole 190 мс).

## Ограничения

* `Vm::eval` не реентерабелен. Нет проверки полноты `match` на этапе компиляции (только ошибка во время выполнения), нет вложенных образцов для таблиц/массивов.
* Нет `try/catch` (ошибки — `Result` и `?`, паники нельзя обработать, кроме `catch_panic` на границе), нет строковой интерполяции, нет вариативных параметров у пользовательских функций.
* Строки неизменяемы, индексирование O(1) только для ASCII.
* Однопоточная VM, GC останавливает мир. Глубина рекурсии — до 400 тыс. кадров (дальше паника `stack overflow`).
* Ctrl-C завершает процесс, в том числе REPL.
