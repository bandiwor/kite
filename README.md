# Kite

Небольшой, быстрый, динамически типизированный язык, в котором почти всё — выражение.
Компилятор и виртуальная машина написаны на Rust, внешних зависимостей нет.

```kite
import "std/math";

union Shape { Circle(r), Rect(w, h) }

impl Shape {
    fn area(self) {
        match self {
            Circle(r) => math.pi * r * r,
            Rect(w, h) => w * h,
        }
    }
}

fn parse_shape(kind, size) {
    const n = size:parse_num()?;                  // ошибка уйдёт вызывающему как значение
    match kind {
        "circle" => Ok(Shape.Circle(n)),
        "square" => Ok(Shape.Rect(n, n)),
        _ => Err(Error("unknown shape: " + kind)),
    }
}

for pair in [["circle", "2"], ["square", "3"], ["blob", "1"], ["circle", "x"]] {
    match parse_shape(pair[0], pair[1]) {
        Ok(s) => print(pair[0], "has area", s:area()),
        Err(e) => print("skipped:", e),
    }
}
```

* **Динамические типы**: `nil`, `bool`, `number` (f64), `string`, `array`, `table`, функции, `struct`, `union`.
* **Выражения везде**: `if`, блоки, `loop`, `while`, `for`, `match` возвращают значения; `{1} + {2}` — корректное выражение.
* **Замыкания** с настоящим захватом переменных; своя свежая переменная на каждую итерацию цикла.
* **Ошибки как в Rust**: `Result`/`Option`, оператор `?`, `panic` для багов; исключений и `try/catch` нет.
* **Типы данных**: настоящие массивы (хранят `nil`, проверяют границы), хеш-таблицы, структуры, tagged-`union` и сопоставление с образцом.
* **Модули**: файлы с `import`/`export`, стандартные модули (`std/math`, `std/fs`, `std/io`) подключаются явно.
* **Без ООП**: методы — это функции из `impl`; особые имена (`add`, `eq`, `str`, `new`, `destroy`, …) перегружают операторы.
* **Быстрый конвейер**: лексер на 8-байтовых токенах → Pratt-парсер с тонким AST → анализатор → компилятор → peephole →
  **регистровая** VM с NaN-boxing, 4-байтовыми инструкциями и mark & sweep GC. REPL — в комплекте.

## Быстрый старт

```sh
cargo build --release
./target/release/kite                      # интерактивный режим (REPL)
./target/release/kite examples/hello.kite  # запустить файл
./target/release/kite -e 'print(1 + 2)'    # выполнить фрагмент
echo 'print("из stdin")' | ./target/release/kite -
```

| опция | что делает |
|---|---|
| `-e, --eval <код>` | выполнить код вместо файла |
| `--dump-ast`, `--dump-bytecode` | напечатать AST / байткод в stderr |
| `--no-opt` | отключить peephole-оптимизатор |
| `--gc-stress` | сборка мусора при каждой возможности (для отладки) |
| `--time` | время фаз компиляции и выполнения |

В REPL многострочный ввод продолжается, пока скобки или строка не закрыты; значение последнего выражения печатается.
Команды: `:help`, `:quit`, `:bytecode`, `:ast`, `:opt`, `:gc`, `:mem`, `:globals`. Для истории и правки строки запускайте `rlwrap kite`.

```
>>> fn double(n) { n * 2 }
>>> double(21) + 0
=> 42
>>> [1, nil, { a: "b" }]
=> [1, nil, {a: "b"}]
```

## Тур по языку

```kite
const PI = 3.14;                       // const нельзя переприсвоить
var x = 10;
x += 10;

const val = loop { break 42; };        // цикл — выражение, break несёт значение
const size = if val > 10 { "big" } else { "small" };

fn add(a, b) { a + b }                 // последнее выражение без `;` — результат
const mul = |a, b| => a * b;           // лямбда
fn counter() {
    var n = 0;
    return || => { n += 1; n };        // замыкание хранит n
}

const xs = [1, 2, 3, 4];               // массив
const doubled = xs:map(|x| => x * 2);  // методы вызываются через `:`
const person = { name: "Ada", age: 36 };  // таблица
person.age += 1;

struct Vec2 { x, y }                   // структура с перегрузкой оператора
impl Vec2 {
    fn add(a, b) { Vec2(a.x + b.x, a.y + b.y) }
    fn str(self) { "(" + self.x + ", " + self.y + ")" }
}
print(Vec2(1, 2) + Vec2(3, 4), doubled, person, counter()(), val);
```

Примеры целиком — в [`examples/`](examples): `fizzbuzz`, `primes`, `closures`, `tables`, `vec2`, `linked_list`, `resources` (деструкторы),
`errors` (`Result` и `?`), `expr` (union + match), `files` (стандартный модуль `std/fs`).

## Справочник

### Значения и операторы

```kite
nil  true  false                     // литералы
42  3.14  1_000  0xFF  0b101  1e-3   // числа — всегда f64
"строка\n"  'или так'  "\u{1F600}"   // строки (UTF-8); escape: \n \t \r \0 \\ \" \' \xHH \u{…}
```

Ложны только `nil` и `false`: `0` и `""` истинны. Приоритеты, от слабых к сильным:

| | |
|---|---|
| `\|\|` | «или»: возвращает операнд, как в Lua (`nil \|\| "d"` → `"d"`) |
| `&&` | «и» |
| `==` `!=` | равенство; разные типы не равны (`1 == "1"` — `false`) |
| `<` `<=` `>` `>=` | числа с числами, строки со строками; иначе паника |
| `\|` · `^` · `&` | побитовые (над i64) |
| `<<` `>>` | сдвиги |
| `+` `-` | сложение; если один операнд — строка, это конкатенация (`"n=" + 5`) |
| `*` `/` `%` | деление на ноль даёт `inf`/`nan`; `%` как `fmod` |
| `-x` `!x` `~x` | унарные |
| `**` | степень, правоассоциативна, сильнее унарного минуса: `-2 ** 2 == -4` |
| `f(x)` `a[i]` `t.name` `x:method(y)` `e?` | постфиксные |

Присваивание (`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `**=`, `&=`, `|=`, `^=`, `<<=`, `>>=`) — **оператор, а не значение**:
`a = b = c`, `while a = b {}`, `if a = 1 {}`, `f(a = 1)` — ошибки компиляции с подсказкой «did you mean `==`?».
Присваивание можно ставить как оператор, как тело `=>`-лямбды или ветки `match` и как последнюю строку блока.

### Переменные

```kite
const PI = 3.14;      // привязка неизменна (содержимое массивов и таблиц менять можно)
var x = 1;            // изменяемая
var y;                // nil
```

Верхний уровень файла — глобальные имена: функции видят объявленное ниже. Внутри функций и блоков имена локальные, область видимости лексическая;
повторное объявление в той же области — ошибка. В REPL глобальные можно объявлять заново.

### Выражения и управление

```kite
const size = if n > 10 { "big" } else if n > 5 { "mid" } else { "small" };
const v = do { var t = compute(); t * 2 };     // блок-выражение: значение последнего выражения без `;`

while cond { … }                  // значение — nil или то, что передал break
const r = loop { …; break 42; }   // бесконечный цикл, значение — break
for i in 0..10 { … }              // диапазон [0, 10); границы вычисляются один раз
for v in array { … }              // значения
for i, v in array { … }           // индекс и значение (для таблицы — ключ и значение)
for v in table { … }              // значения: сначала подряд идущие ключи 0, 1, …, потом в порядке вставки
for ch in "héy" { … }             // символы (при двух переменных первая — смещение в байтах)
break; break value; continue;     // можно и внутри выражения: f(1, if c { break 5 } else { 2 })
return; return value;             // в любом месте выражения
```

Точка с запятой не нужна после выражения, заканчивающегося `}`.

**Блок — полноценный операнд**: `{1} + {2}`, `x * { var t = f(); t + 1 }`, `|a| => {a} + {1}`. В позиции выражения `{` — блок, если он не похож
на таблицу (`{}`, `{k: …}`, `{"k": …}`, `{1: …}`, `{[k]: …}`, `{a, …}`); одиночное `{name}` — таблица-сокращение, если рядом нет бинарного оператора.
Блок, начинающийся с вызова метода (`{ log:push(1); … }`), остаётся блоком, пока вокруг `:` нет пробелов; `{ key: f(1) }` с пробелом — таблица.

### Функции и замыкания

```kite
fn add(a, b) { return a + b; }       // объявление; последнее выражение без `;` — результат
fn sq(x) { x * x }
const mul = |a, b| => a * b;         // лямбда-выражение
const inc = |x| { var y = x + 1; y } // лямбда-блок (`=> { … }` тоже блок; `=> { key: v }` — таблица)
const k = || => 42;
const anon = fn (a) { a + 1 };       // анонимная функция

fn counter() {
    var n = 0;
    return || => { n += 1; n };      // n живёт, пока жива лямбда
}
```

Число аргументов проверяется строго. Хвостовые вызовы не растут по стеку (`return f(x)`). Рекурсия по имени работает и для `const f = |x| => … f(x - 1)`.

### Массивы

Настоящий массив: позиции `0..len`, любые значения (в том числе `nil`), проверка границ.

```kite
const a = [10, nil, 30];           // nil — обычный элемент: a:len() == 3
a:push(40, 50);  a:push(60);       // push возвращает новую длину
a[0] += 5;                         // читать и писать можно только существующие позиции
a[9];  a[-1];  a[1.5];  a[3] = 0;  // паника: index out of bounds / must be a non-negative integer
a:get(9);                          // None; a:get(0) — Some(15): проверяемый доступ возвращает Option
a:pop();                           // Some(60) или None (nil может быть элементом, поэтому Option)
for v in a { … }   for i, v in a { … }
print(a:map(|x, i| => x), array.new(3, 0), [1, 2, 3]:slice(1));
```

Массив не растёт присваиванием (`a[a:len()] = v` — паника, используйте `push`) и никогда не превращается в хеш-таблицу. `==` сравнивает массивы
по идентичности (как таблицы); `copy()` делает поверхностную копию.

| | |
|---|---|
| `push(v…)` `pop()` `insert(i, v)` `remove(i)` `clear()` | изменение (`i` для `insert` ≤ длины); `pop` → `Option`, `remove` → элемент |
| `get(i)` `first()` `last()` `index_of(v)` `contains(v)` | проверяемый доступ и поиск → `Option` (`contains` → bool) |
| `slice(from, to?)` `concat(b…)` `copy()` `extend(b)` `reverse()` `sort(less?)` | `slice/concat/copy` — новый массив; `extend/reverse/sort` — на месте, возвращают массив; сортировка устойчивая |
| `map(f)` `filter(f)` `reduce(f, init?)` `each(f)` | `f(x)` или `f(x, i)`; `map`/`filter` возвращают массив |
| `join(sep?)` `keys()` `values()` `has(i)` `len()` | |
| `array.new(n, fill?)` | массив из `n` копий |

### Таблицы

Хеш-таблица с сохранением порядка вставки.

```kite
const t = { name: "kite", "two words": 2, [1 + 1]: "computed", 3: "x" };
t.name = "KITE";  t["k"] = 1;  t.k += 1;
t.name = nil;                      // присвоение nil удаляет ключ
print(t:len(), t.missing);         // отсутствующий ключ — nil
```

Ключ — любое значение, кроме `nil` и `NaN`. Строки сравниваются по содержимому, числа — по значению (`1 == 1.0`, `-0 == 0`), остальное — по идентичности.
`{ x }` — сокращение для `{ x: x }`.

Методы таблицы: `len keys values has remove map filter reduce each` (`t:keys()`, `t:has("x")`, …). Поле таблицы с тем же именем выигрывает у метода:
`{ keys: |self| => 1 }:keys()` вызывает поле, `table.keys(t)` — библиотечную версию.

### Строки

Строки неизменяемы, в UTF-8; индексы и длина считаются в символах Unicode, отрицательные индексы — с конца.

```kite
"héllo":len()            // 5
"héllo"[1]               // "é"      "héllo"[-1] — "o"      "héllo"[10] — nil
"héllo":sub(1, 3)        // "él"     "héllo":sub(-3) — "llo"
"a,b,c":split(",")       // ["a", "b", "c"]      ["a", "b"]:join("-") — "a-b"
"{} + {:.2} = {:>6}|{:<4}|":format(1, 3.14159, "x", "y")   // "1 + 3.14 =      x|y   |"
"42":parse_num()         // Ok(42)               "x":parse_num() — Err(Error)
```

Методы: `len upper lower trim reverse sub find contains starts_with ends_with split join replace rep chars byte char format parse_num`.
`find` возвращает индекс или `nil`. В `format`: `{}` — значение, `{:.N}` — число с N знаками, `{:>W}` / `{:<W}` — выравнивание в поле шириной W, `{{` и `}}` — скобки.
`"n=" + 5`, `"ok: " + true` склеивают, приводя второй операнд к строке (для структур вызывается `str`).

### Структуры, перегрузки, `new` и `destroy`

```kite
struct Vec2 { x, y }               // фиксированный набор полей, изначально nil

impl Vec2 {
    fn new(self, x, y) { self.x = x; self.y = y; }    // конструктор: Vec2(1, 2)
    fn add(a, b) { Vec2(a.x + b.x, a.y + b.y) }       // a + b
    fn eq(a, b)  { a.x == b.x && a.y == b.y }         // a == b
    fn str(a)    { "(" + a.x + ", " + a.y + ")" }     // print / str / конкатенация
    fn length(self) { (self.x * self.x + self.y * self.y) ** 0.5 }
    fn destroy(self) { print("bye", self) }           // при сборке мусора и при выходе
}

const v = Vec2(1, 2) + Vec2(3, 4);
print(v, v.x, Vec2.add(v, v), v:length());            // v:f(a) то же, что Vec2.f(v, a)
```

Без `new` конструктор принимает значения полей по порядку. Результат конструктора — всегда новый экземпляр.

| имя | когда вызывается |
|---|---|
| `new(self, …)` | `Type(…)` |
| `destroy(self)` | экземпляр недостижим для GC, явный `destroy(x)`, завершение программы |
| `add sub mul div rem pow (a, b)` | бинарные операторы (ищутся у левого, затем у правого операнда) |
| `neg(a)` | унарный минус |
| `eq(a, b)` | `==` и `!=` |
| `lt(a, b)` `le(a, b)` | `<`, `>` (через `lt`), `<=`, `>=` (через `le`, иначе `!lt`) |
| `str(a)` | `print`, `str()`, конкатенация со строкой |
| `get(a, k)` `set(a, k, v)` | `a[k]`, `a[k] = v` и обращения к несуществующему полю |
| `call(self, …)` | вызов экземпляра как функции |

Остальные функции из `impl` — обычные: `Type.name(…)` или `obj:name(…)`; так можно определить и `len`. `type(x)` для экземпляра возвращает имя структуры.
Деструкторы вызываются в порядке создания; ошибка в `destroy` печатается как предупреждение и не прерывает программу.

### Union и `match`

`union` — размеченное объединение (как `enum` в Rust): у каждого варианта своё имя и набор полей.

```kite
union Shape {
    Circle(radius),          // вариант с данными
    Rect(w, h),
    Point,                   // вариант без данных (единственный общий экземпляр)
}

const c = Shape.Circle(2);
print(c, c.radius, type(c), type(Shape));      // Circle(2) 2 Shape union
c.radius = 5;                                  // поля вариантов читаются и пишутся по имени
const circles = [1, 2]:map(Shape.Circle);      // конструктор — обычная функция

impl Shape {                                   // impl, перегрузки и destroy — как у структур
    fn area(self) {
        match self {
            Circle(r) => 3 * r * r,
            Rect(w, h) => w * h,
            Point => 0,
        }
    }
}
print(c:area());
```

`match` — выражение: берётся первая подошедшая ветка, значение — её тело. Если ничего не подошло — паника `no match arm matched the value …`.
Выражение вычисляется один раз.

| образец | значит |
|---|---|
| `_` | что угодно |
| `name` (с маленькой буквы) | что угодно, значение связывается с `name` |
| `0`, `-1`, `"s"`, `true`, `false`, `nil` | равенство с литералом |
| `Circle(r)`, `Rect(w, _)` | вариант (любого union) с таким именем; поля по порядку, число образцов обязано совпасть |
| `Circle` | вариант с любым числом полей |
| `Shape.Circle(r)` | то же, но ещё и проверка, что значение из `Shape` (`Shape` — любое выражение-путь, например `mod.Shape`) |
| `Pt(x, 0)` | экземпляр структуры `Pt`, поля по порядку |
| `p \| q` | любая из альтернатив; все должны связывать одни и те же имена |
| `pat if cond` | образец + охранное условие (видит связанные имена; если ложно — следующая ветка) |

Образцы вкладываются: `Add(Num(0), r) | Add(r, Num(0)) => simplify(r)`. Имя образца с заглавной буквы — вариант, с маленькой — привязка.
Ветки разделяются запятой; тело — выражение, блок или присваивание: `n => total += n`, `_ => {}`. Связанные имена можно захватывать замыканиями.

### Ошибки: `Result`, `Option` и паники

Как в Rust, ошибки бывают двух видов.

**Ожидаемые неудачи** (файла нет, строка не число, пустой список) — это **значения**: `Result` (`Ok(v)` / `Err(e)`) и `Option` (`Some(v)` / `None`).
Это обычные union'ы, доступные везде без импорта; `Error` — стандартный тип ошибки с полями `message` и `kind`.

```kite
fn parse_age(s) {
    const n = s:parse_num()?;                // Err(..) сразу возвращается из parse_age, Ok(v) даёт v
    if n < 0 { return Err(Error("negative age"):with_kind("range")); }
    Ok(n)
}

match parse_age("42") {
    Ok(n) => print("age", n),
    Err(e) if e.kind == "range" => print("bad range:", e),
    Err(e) => print("error:", e),            // print(e) показывает message
}
```

Оператор `expr?` разворачивает `Ok`/`Some` и возвращает `Err`/`None` *как есть* из ближайшей функции (лямбда — отдельная функция); он может стоять где угодно в выражении:
`Ok(a? + b?)`, `f(x?)`, `r?.name`. Значение другого типа — паника. На верхнем уровне модуля `?` запрещён (как `return`).

| `Option` | |
|---|---|
| `is_some() is_none()` | проверки |
| `unwrap() expect(msg)` | значение или паника |
| `unwrap_or(d) unwrap_or_else(f)` | значение или запасное |
| `map(f) and_then(f) or_else(f) filter(p)` | преобразования |
| `ok_or(err)` | `Option` → `Result` |

| `Result` | |
|---|---|
| `is_ok() is_err()` | проверки |
| `unwrap() expect(msg) unwrap_err()` | значение (ошибку) или паника |
| `unwrap_or(d) unwrap_or_else(f)` | `f` получает ошибку |
| `map(f) map_err(f) and_then(f) or_else(f)` | преобразования |
| `ok() err()` | `Result` → `Option` |

`==` для них структурное (`Some(1) == Some(1)`). `Error("msg")` создаёт ошибку, `:with_kind("parse")` задаёт категорию для сопоставления; `Err` может нести любое значение.
Из `nil` в `Option` превращает `option(x)`. Свои функции, которые могут не получиться по внешним причинам, тоже возвращайте как `Result`.

**Паники** — баги и невозможные операции: `1 + nil`, индекс вне диапазона, вызов `nil`, неверное число аргументов, `assert`, `panic("msg")`, `unwrap()` у `None`,
неисчерпывающий `match`, переполнение стека. Паника завершает программу: печатается сообщение, фрагмент исходника и стек вызовов, деструкторы выполняются.

```kite
assert(1 + 1 == 2, "math is broken");
const r = catch_panic(|| => 1 + nil);           // Err(Error) с kind "panic"
panic("boom");                                  // завершает программу
```

`catch_panic(f, args…)` возвращает `Ok(результат)` или `Err(Error)`. Его место — на границе (тесты, REPL, обработчик запросов), а не в обычной логике.

### Модули и стандартные модули

Файл — это модуль. Его верхнеуровневые имена **приватны**, наружу уходит только то, что помечено `export` (`export var/const/fn/struct/union`).
Модуль выполняется один раз при первом `import` и возвращает таблицу экспортов:

```kite
// geometry.kite
var created = 0;                          // приватное состояние модуля
export struct Point { x, y }
export fn origin() { created += 1; Point(0, 0) }
export fn how_many() { created }

// main.kite
import "geometry";                         // имя берётся из пути: geometry
import "lib/geometry.kite" as geo;         // или своё имя
import { origin, Point } from "geometry";  // отдельные имена; нет такого экспорта — ошибка
print(geometry.origin(), geometry.how_many());
```

Путь ищется относительно файла с `import` (`путь`, `путь.kite`, `путь/mod.kite`; для REPL и `-e` — относительно текущей папки). Модуль кэшируется по каноническому пути,
циклический импорт — ошибка. Верхнеуровневые функции модуля видят друг друга независимо от порядка. Экспортируемые `var` — снимок значения на конец инициализации
(для общего изменяемого состояния экспортируйте функции). `import`/`export` допустимы только на верхнем уровне файла, `return` и `?` на верхнем уровне модуля запрещены.
В обычном скрипте `export` игнорируется.

**Стандартные модули** встроены в язык, но не глобальны — их нужно подключить `import` (путь начинается с `std/`):

```kite
import "std/math";                       // math.sqrt(2)
import { floor, pi } from "std/math";
import "std/fs" as files;                // files.read(…)
```

| модуль | содержимое |
|---|---|
| `std/math` | `floor ceil round trunc abs sqrt sin cos tan asin acos atan atan2 exp ln log2 log10 pow min max sign random seed`, `pi e huge` |
| `std/fs` | файлы, папки и пути (см. ниже) |
| `std/io` | ввод и вывод: stdout, stderr, stdin (см. ниже) |

Неизвестное имя `std/…` — ошибка со списком доступных модулей. Каждый файл подключает нужные ему стандартные модули сам.

#### `std/fs`

Операции над файлами целиком (без дескрипторов). Всё, что может не получиться из-за внешнего мира, возвращает `Result`; `Err(Error)` несёт `kind`:
`"not_found"`, `"permission"`, `"exists"`, `"utf8"` (файл не текст) или `"io"`, а сообщение содержит путь. Передать не строку вместо пути — баг, то есть паника.

```kite
import "std/fs";
fs.write("notes.txt", "one\ntwo\n")?;                 // Ok(nil)
const text = fs.read("notes.txt")?;                    // Ok("one\ntwo\n")
for line in fs.lines("notes.txt")? { print(line); }    // без символов конца строки
fs.append("log.txt", "started\n")?;                    // создаёт файл, если его нет

match fs.read("config.kite") {
    Ok(src) => print(src:len()),
    Err(e) if e.kind == "not_found" => print("using defaults"),   // "config.kite: no such file or directory"
    Err(e) => panic(e),
}
```

| | |
|---|---|
| `read(p)` `lines(p)` `size(p)` | `Ok(текст)` / `Ok([строки])` / `Ok(байты)` |
| `write(p, s)` `append(p, s)` | `Ok(nil)`; `write` создаёт или обрезает файл |
| `list(dir)` | `Ok([имена])`, отсортированные |
| `mkdir(p)` | создаёт и промежуточные папки; существующая — не ошибка |
| `remove(p)` `remove_all(p)` | файл или пустая папка / файл или дерево целиком |
| `rename(a, b)` `copy(a, b)` | `Ok(nil)` |
| `exists(p)` `is_file(p)` `is_dir(p)` | `bool` (ошибки доступа читаются как «нет») |
| `cwd()` | `Ok(путь)` |
| `join(a, b, …)` `basename` `dirname` `stem` `ext` | строки-пути без обращения к диску; `ext("Makefile")` → `nil` |

#### `std/io`

Глобальные `print`, `write` и `input` остаются под рукой; модуль добавляет stderr, чтение всего ввода и явный сброс буфера. Вывод идёт в тот же
буферизованный stdout, что и у `print`, поэтому порядок строк сохраняется; `eprint`/`ewrite` сначала сбрасывают stdout, потом пишут в stderr.

```kite
import "std/io";
io.writeln("x = ", 42, ", ", [1, 2]);      // x = 42, [1, 2]
io.eprint("warning:", "disk is full");     // в stderr, через пробел

while true {
    match io.prompt("> ") {                // печатает приглашение, читает строку
        Some(line) => io.writeln("you said: ", line),
        None => break,                     // конец ввода (Ctrl-D)
    }
}
const rest = io.lines()?;                  // Ok([строки до конца ввода])
```

| | |
|---|---|
| `write(…)` `writeln(…)` | значения без разделителя; `writeln` добавляет `\n` |
| `print(…)` | как глобальный `print`: через пробел и с `\n` |
| `eprint(…)` `ewrite(…)` | то же в stderr (`eprint` — как `print`, `ewrite` — как `write`) |
| `flush()` | `Ok(nil)`; сбросить буфер stdout |
| `read_line()` | `Some(строка)` без `\n`/`\r\n`, `None` в конце ввода; невалидный UTF-8 заменяется на `�` |
| `prompt(текст)` | вывести `текст` без перевода строки и вызвать `read_line()` |
| `read_all()` `lines()` | `Ok(весь остаток ввода)` / `Ok([строки])`; `Err` с `kind` `"utf8"` или `"io"` |

### Встроенные функции и методы

Глобально доступно только то, что не принадлежит какому-то типу:

| | |
|---|---|
| ввод/вывод | `print(…)` (с переводом строки), `write(…)`, `input(prompt?)` |
| типы | `type(x)`, `str(x)`, `num(x)` (`nil`, если не число; с причиной — `s:parse_num()`) |
| ошибки | `assert(c, msg?)`, `panic(msg)`, `catch_panic(f, args…)`, `option(x)`; типы и значения `Option Some None Result Ok Err Error` |
| система | `clock()`, `time()`, `exit(code?)`, `gc()` (возвращает освобождённые байты), `mem()`, `destroy(x)` |

Всё, что работает с конкретным типом, — **метод** этого типа (`x:name(…)`), а не глобальная функция: `a:push(1)`, `t:keys()`, `s:upper()`, `opt:unwrap()`.
Пространства имён типов (`array`, `string`, `table`) тоже глобальны и хранят те же функции: `string.upper(s)` ≡ `s:upper()`, `array.new(n, fill)` — конструктор.
Структуры и union получают методы из своих `impl`.

## Устройство

```
 исходник ──► lexer ──► parser ──► analyzer ──► compiler ──► peephole ──► VM
              Vec<Token>  тонкий AST  слоты, upvalue,  байткод       слияние        NaN-boxing, GC,
              (8 байт)    + Sym       const, break     (слова по     инструкций     замыкания
                                                        4 байта)
```

| модуль | суть |
|---|---|
| `lexer.rs`, `token.rs` | один проход по байтам; токен — ровно 8 байт (`kind:u8 + len:24 бита + start:u32`); **ничего не разбирает** (числа и escape-последовательности декодирует парсер по требованию) |
| `parser.rs`, `ast.rs` | Pratt-парсер; узлы по 16 байт в одном `Vec` с индексами `u32`, списки детей — диапазоны общего массива; идентификаторы интернируются, **строковые литералы остаются диапазонами исходника** |
| `analyzer.rs` | имена (local / upvalue / global), слоты кадра, захваченные переменные, `const`, области модулей, образцы `match` |
| `compiler.rs` | **регистровый** байткод: локальные — первые регистры кадра, временные выделяются стопкой выше, результат пишется сразу в целевой регистр; сворачивание констант; сравнение + переход — одна инструкция; условия `&& \|\| !` — чистый поток управления; `match` в цепочку проверок |
| `op.rs`, `peephole.rs` | `Op` — ровно 4 байта: код + три операнда-регистра `R[a] = R[b] op R[c]` (либо `u8,u16` / `u8,i16` / `U24` / `I24`); «двойные» инструкции с вторым словом `Ext` для длинных переходов и больших индексов; peephole протягивает переходы, убирает мёртвый код и `Move(a, a)`, а `Call+Return → TailCall` делает финализация функции |
| `vm.rs` | цикл `match` по `Op`; кадр — окно регистров `R[0..nregs)` в общем стеке значений, результат вызова пишется прямо в регистр вызывающего; `ip/base/consts` в локальных переменных; вызовы замыканий и перегрузок операторов без рекурсии на стеке Rust |
| `value.rs`, `object.rs`, `heap.rs`, `table.rs` | NaN-boxing, объекты кучи (строки, таблицы, **массивы**, функции, экземпляры), mark & sweep с финализаторами, упорядоченная хеш-таблица |
| `builtins.rs`, `fslib.rs`, `iolib.rs`, `prelude.kite` | встроенные функции и методы типов, `std/fs`, `std/io`, а `Option`/`Result`/`Error` написаны на самом Kite и загружаются при старте |
| `pool.rs` | аллокатор малых объектов для бинарника (отключается фичей `system-alloc`) |

Подробности, инварианты и рецепты расширения (новый оператор, опкод, встроенная функция, хук, тип объекта, стандартный модуль) — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Тесты и инструменты

```sh
cargo test                                # юнит-тесты, tests/cases/*.kite (4 прогона), примеры, байткод
cargo build --release
python3 tools/fuzz.py 300 1               # дифференциальный фаззер программ (оракул на Python)
python3 tools/fuzz_match.py 1000 1        # match: случайные значения × образцы
python3 tools/fuzz_array.py 1000 1        # массивы: случайные операции против списков Python
python3 tools/reduce.py SEED              # минимизатор упавшей программы

cargo build --release --features system-alloc # без пулового аллокатора (для valgrind)
```

Каждый кейс из `tests/cases` (`// expect:` — ожидаемый вывод, `// error:` — ожидаемая ошибка) запускается обычным способом, без оптимизатора,
со сборкой мусора на каждом safe point и ещё раз через настоящий бинарник (с пуловым аллокатором). Фаззеры сравнивают Kite с независимыми реализациями
на Python во всех режимах.

## Производительность

Один поток, `cargo build --release`, общая 4-ядерная машина (лучшее из 5, разброс ±10%); программы — `examples/bench/*.kite`, запуск — `tools/bench.sh`:

| бенчмарк | время |
|---|---|
| `fib(35)` (рекурсия, 30 млн вызовов) | ≈ 0.60 с |
| цикл `while` на 100 млн итераций (`sum += i; i += 1`) | ≈ 0.60 с |
| `for i in 0..50e6 { sum += i % 7 }` | ≈ 0.43 с |
| 10 млн вызовов замыкания с изменением upvalue | ≈ 0.26 с |
| 2 млн коротко живущих `{a: i, b: [i, i+1]}` | ≈ 0.19 с |
| решето Эратосфена до 5 млн (`push` + индексы) | ≈ 0.31 с |
| 300 тыс. строк: склейка, `join`, `split`, 20 тыс. `acc = acc + "x"` | ≈ 0.22 с |
| 3 млн `acc = acc + one` с перегрузкой `add` и конструктором `new` | ≈ 0.24 с |
| 1 млн записей в хеш-таблицу + чтение + 2 млн `push` и чтений | ≈ 0.25 с |

Для ориентира на той же машине: `fib(32)` — Kite ≈ 0.15 с, CPython 3.13 ≈ 0.29 с; пустой цикл на 20 млн итераций — Kite ≈ 0.11 с, CPython ≈ 0.6 с.
Регистровая схема против прежней стековой на тех же программах: циклы и арифметика быстрее на 15–20 % (нет `Push`/`Pop`, сравнение с переходом — одна инструкция), вызовы функций медленнее на 10–15 % (каждый кадр обнуляет свои регистры, чтобы сборщик не видел мусор).
Запуск пустой программы ≈ 2 мс. Компиляция: файл в 4 МБ (60 тыс. строк, 1.6 млн токенов) — около 0.16 с (≈ 26 МБ/с).

Что оказалось узким местом и как исправлено (аллокатор, перегрузки операторов без вложенного интерпретатора, слитые записи, ленивые хеши строк) — в ARCHITECTURE.md.

## Ограничения

* `Vm::eval` не реентерабелен. Нет проверки полноты `match` на этапе компиляции (только паника при исполнении) и образцов для массивов и таблиц.
* Нет `try/catch` (ошибки — `Result` и `?`; паника необратима, кроме `catch_panic` на границе), нет строковой интерполяции и вариативных параметров у пользовательских функций.
* Строки неизменяемы, индексирование O(1) только для ASCII. `acc = acc + "x"` в цикле квадратичен, как и в большинстве языков.
* У чисел нет методов: математика — функции модуля `std/math`.
* Однопоточная VM, GC останавливает мир. Глубина рекурсии — до 400 тыс. кадров (дальше паника `stack overflow`).
* Функции ограничены 250 регистрами: локальные переменные плюс временные значения самого глубокого выражения (ошибка компиляции, если не помещается).
* Файловый ввод-вывод — только целыми файлами (нет дескрипторов, потоков, сети).
* Ctrl-C завершает процесс, в том числе REPL.
